# MVP 业务决策与验收

日期：2026-10-10。以下默认规则已由用户在实现会话中确认，作为产品设计及技术方案待定项的本次定稿。

## 业务规则

1. 签到窗口为 `[开始前15分钟, 开始后15分钟)`，截止时刻拒绝签到。每日教室码按 Asia/Shanghai 日期校验；连续错误尝试受限。
2. 个人预约结束前可取消，包括已签到预约；已结束预约不可取消。已批准教室申请只能在开始前撤销，待审批申请可撤销。
3. 维修保留既有预约和申请记录，立即阻止新预约、签到及新审批。维修覆盖签到截止时，未签到记录自动释放并注明维修取消，不产生违约。已签到和整室记录保留；维修验收只解除该工单来源。
4. 同一用户不能预约重叠时段；首版允许最多提前30天预约，单次默认最多4小时，可由管理员调整为1至12小时。M1按整点小时，M2精确到分钟；均使用半开区间，必须在同日开放时间内。
5. APPLICANT及ADMIN可提交整室申请。拒绝与个人预约或已批准申请相交的审批；有维修限制时拒绝审批，包含未来时段。院系限制适用于申请和报修，管理员可维护全部资源。
6. 工单流程为上报、派单、维修、完工、验收；验收驳回返回维修中并保留限制。已派单、尚未开始时管理员可改派；首版不提供工单删除或误报关闭。
7. 演示数据为计算机学院CS、艺术学院ART及公共空间；3间教室，每间24座，开放08:00至22:00，偶数座有插座。演示签到码246810仅在显式初始化时设为当天。

公共层由资源应用统一承担身份、空间、预约及占用协议；流程应用承担申请和工单。本仓库按模块实施，不代替课程团队的人员分工决定。服务器规格、租期、域名及部署凭据缺失不阻塞本地实现，实际云部署时补充。

## 2026-10-15新增注册与账号管理

用户追加要求：提供注册入口和管理员账号管理。学生可在登录页进入注册，填写用户名、姓名、院系、密码和确认密码；注册角色固定为学生，其他角色由管理员分配。注册不自动登录，成功后返回登录页并仅预填用户名。

管理员可以搜索分页查看全部账号、创建账号、编辑姓名/院系/角色、启用或停用、重置密码。用户名唯一且不区分大小写，不能修改；密码至少8个字符且UTF-8最多72字节。停用保留历史，不提供删除。修改权限、院系、启停或密码后使目标已有会话失效；单改姓名不注销。管理员不能误停用自己或移除自己的管理员身份，并保护最后一个启用的管理员。
